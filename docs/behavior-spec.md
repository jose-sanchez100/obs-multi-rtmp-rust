# Behavior specification: C++/Qt plugin `obs-multi-rtmp`

Source: the original C++ plugin source (a fork of SoraYuki's obs-multi-rtmp, https://github.com/sorayuki/obs-multi-rtmp), branch `feature/rust-session-engine` (last commit `27fbf15`), version `0.8.0.0` (`buildspec.json`), OBS 33.0.1 headers.
Goal: reimplement it with all logic in Rust and a minimal Qt dock, with feature parity and **the same `obs-multi-rtmp.json` format**.
`file:line` references point into `src/` unless stated otherwise. "OBS:" marks code from `.deps/obs-studio-33.0.1`.

## 1. Configuration persistence

### 1.1 Location and I/O
- Path: `obs_frontend_get_current_profile_path()` + `"/obs-multi-rtmp.json"` (`output-config.cpp:258-261`, `271-275`). There is one file per OBS profile.
- **Write**: `os_quick_write_utf8_file_safe(path, content, len, marker=true, "tmp", "bak")` (`output-config.cpp:263`). It first writes `obs-multi-rtmp.json.tmp` **with a UTF-8 BOM** (marker=true), then atomically replaces the file, keeping the previous one as `obs-multi-rtmp.json.bak` (OBS: `libobs/util/platform.c:286-326`). The return value is ignored.
- **Read**: `os_quick_read_utf8_file` (strips the BOM). If the file does not exist, `LoadMultiOutputConfig()` returns false and the configuration stays empty (`output-config.cpp:270-288`).
- Content: nlohmann `json.dump()`, **compact, no whitespace, keys sorted alphabetically** (nlohmann::json uses `std::map`). Non-ASCII characters are written as raw UTF-8. For a compatible reimplementation, `serde_json` + `BTreeMap` (without `preserve_order`) plus writing the BOM is enough.
- Log: `"[obs-multi-rtmp] Save %d targets, %d video configs, %d audio configs"`. The video and audio counters count **all** configs, not just the saved ones (`:82-112`).

### 1.2 When it is loaded and saved
| Moment | Action | Ref |
|---|---|---|
| `obs_module_load` → dock constructor | `LoadConfig()`: clears the widgets, `GlobalMultiOutputConfig() = {}` and loads the file | `obs-multi-rtmp.cpp:280`, `486-504` |
| `OBS_FRONTEND_EVENT_PROFILE_CHANGED` | `LoadConfig()` (targets were already stopped with `Stop()` in the same event) | `:713-716` |
| OK in "Edit targets" | `ApplyEditedConfig` → `SaveConfig()` | `:560` |
| Drag-reordering in the dock | `OnOutputMoved` → `SaveConfig()` | `:482` |
| A row's "enabled" checkbox | `SetEnabled` → `SaveMultiOutputConfig()` | `push-widget.cpp:1236` |
| `OBS_FRONTEND_EVENT_EXIT` | `SaveConfig()` | `obs-multi-rtmp.cpp:709-712` |

`PROFILE_CHANGING` is not handled (not needed: every change is saved immediately).

### 1.3 Exact JSON schema

Root (object):

| Key | Type | Notes |
|---|---|---|
| `targets` | array of Target objects | Order = order of the dock rows |
| `video_configs` | array of VideoConfig | **On save, only those referenced by some target are written** (`output-config.cpp:94-99`) |
| `audio_configs` | array of AudioConfig | Same: only referenced ones (`:101-106`) |

**Target** (`SaveTarget` `:21-36`, `LoadTargetConfig` `:120-138`):

| Key | Type | On load if missing or wrong type | Notes |
|---|---|---|---|
| `id` | string | **target is discarded** | Random id (see 2.5) |
| `name` | string | `""` | |
| `protocol` | string | `"RTMP"` (backward compatibility) | `RTMP`, `SRT_RIST`, `RTMP_RUST`, `WHIP` |
| `service-param` | object | `null` (`nlohmann::json{}` is **null**, not `{}`) | `obs_data` JSON of the `obs_service` settings. Saved as is, including as `null` |
| `output-param` | object | `null` | JSON of the `obs_output` settings (for RTMP_RUST: `server`, `key`, `backup_server`, `backup_key`) |
| `sync-start` | bool | `false` | |
| `sync-stop` | bool | **value of `sync-start`** (migration: there used to be a single checkbox) | |
| `enabled` | bool | `true` | New key |
| `video-config` | string | absent (= "same as the OBS stream") | VideoConfig id or a marker (2.2). Only written if it has a value |
| `audio-config` | string | absent | Same as `video-config` |

**VideoConfig** (`SaveVideoConfig` `:38-49`, `LoadVideoConfig` `:140-154`):

| Key | Type | Default | Notes |
|---|---|---|---|
| `id` | string | discarded if missing | |
| `encoder` | string | `""` | OBS encoder type id (`obs_x264`, `jim_nvenc`…) |
| `param` | object | `null` | Encoder settings (`obs_data` JSON) |
| `scene` | string | absent = program scene (main mix) | Scene name |
| `resolution` | string | absent = OBS output resolution | Free text; at start the regex `\s*(\d{1,5})\s*x\s*(\d{1,5})\s*` is applied (lowercase `x` only), `push-widget.cpp:451` |
| `fps-denumerator` | **integer** | `1` | FPS divisor, 1..4 in the UI (sic: "denumerator") |

**AudioConfig** (`:58-74`, `:164-187`):

| Key | Type | Default | Notes |
|---|---|---|---|
| `id` | string | discarded if missing | |
| `encoder` | string | `""` | |
| `param` | object | `null` | |
| `mixerId` | integer | `0` | Mixer track (0..5) for output track 0 |
| `audioTracks` | array of `{mixer_track:int, output_track:int}` | `[]` | Extra tracks (VOD track). Non-object elements are ignored; missing keys default to 0 |

Tolerance rules (`json-util.hpp:7-22`, `output-config.cpp:189-241`):
- `GetJsonField<T>` is strict: `int` requires `is_number_integer()` (a `2.0` counts as absent), `bool` requires a boolean and `json` requires an object.
- Non-object array entries are skipped. Malformed JSON produces an error log and an **empty** configuration, without failing (`:237-240`).
- `DeserializeMultiOutputConfig` (import and dialog) returns `nullopt` only if the text is not valid JSON (`:247-255`).

Example (real format, indented here for readability):
```json
{"audio_configs":[{"audioTracks":[{"mixer_track":1,"output_track":1}],"encoder":"ffmpeg_aac","id":"3021","mixerId":0,"param":{"bitrate":160}}],
 "targets":[{"audio-config":"3021","enabled":true,"id":"1187","name":"YouTube","output-param":{"bind_ip":"default","drop_threshold_ms":700,...},
   "protocol":"RTMP","service-param":{"key":"xxxx","server":"rtmp://a.rtmp.youtube.com/live2","use_auth":false},
   "sync-start":true,"sync-stop":true,"video-config":"<OBS_STREAMING_ENCODER>"}],
 "video_configs":[]}
```
The `*-param` objects contain **all** property keys, including those at their default value, because the properties widget copies defaults as user values (6.4).

### 1.4 Export / import ("Edit targets" dialog)
- **Export** (`edit-targets-dialog.cpp:293-322`): first `CommitCurrent()`. Opens a `QFileDialog::getSaveFileName` with default name `obs-multi-rtmp-config.json` and filter `JSON (*.json)`, appending `.json` if missing. The content is `SerializeMultiOutputConfig(dialog working copy)`: the same format as the profile, also with config GC, but **without BOM** (QFile). Stream keys are included in plain text. On failure it shows `Error.ExportConfig`.
- **Import** (`:324-378`): file picker, read, `DeserializeMultiOutputConfig` (nlohmann accepts a BOM), and error `Error.ImportConfig` if it cannot be opened or parsed. Asks for confirmation `Question.Title` / `Question.Import` (Yes/No). Then destroys the pages, replaces the dialog's working copy and calls `RebuildTargets()`. **The global configuration is not touched until OK is pressed.** Active targets are not stopped, even though the text says so (see 7.3).

## 2. Data model

### 2.1 Structures (`output-config.h`)
```
VideoEncoderConfig { id, encoderId, fpsDenumerator=1, encoderParams: json, outputScene: opt<string>, resolution: opt<string> }   :13-20
AudioTrackConfig   { mixer_track:int, output_track:int }                                                                    :23-26
AudioEncoderConfig { id, encoderId, encoderParams: json, mixerId=0, audioTracks: list<AudioTrackConfig> }                   :29-35
OutputTargetConfig { id, name, protocol="RTMP", syncStart=false, syncStop=false, enabled=true,
                     serviceParam: json, outputParam: json, videoConfig: opt<string>, audioConfig: opt<string> }            :39-56
MultiOutputConfig  { targets, videoConfig, audioConfig: list<shared_ptr<...>> ; Find*, GenerateId }                          :60-70
GlobalEditSnapshot { activeTargetIds, activeVideoConfigIds, activeAudioConfigIds }                                          :72-76
GlobalConfigUpdateContext { updatedVideoConfigIds, updatedAudioEncoderNames, notices }                                      :78-82
```
There is a global singleton `GlobalMultiOutputConfig()` (`output-config.cpp:14-18`). Targets, video configs and audio configs are `shared_ptr`s shared between the global configuration and each `PushWidget`.

### 2.2 Markers ("same as OBS"), `helpers.h:8-13`
| Value in `video-config`/`audio-config` | Meaning |
|---|---|
| absent, `""` or `"<OBS_STREAMING_ENCODER>"` | Reuses the encoder of `obs_frontend_get_streaming_output()` (video, or audio of track 0) |
| `"<OBS_RECORDING_ENCODER>"` | Reuses the encoder of `obs_frontend_get_recording_output()` |
| anything else | Id of one of the plugin's own VideoConfig/AudioConfig entries |

`IsSpecialEncoder(id)` is true only for the two markers (not for `""` nor for absence). At runtime, `""` is equivalent to STREAMING (`push-widget.cpp:512`, `554`).

### 2.3 Encoder sharing
- Several targets can point to the **same id** of a VideoConfig or AudioConfig, and then share **the same** `obs_encoder_t` **instance**. The encoder is looked up by name with `obs_get_encoder_by_name`:
  - video: `"multi-rtmp-venc" + videoConfigId` (`push-widget.cpp:440-442`)
  - audio: `"multi-rtmp-aenc" + audioConfigId + "-track-idx-" + N`, where N is the output track (0 for the main one) (`:444-446`)
- The first target to start creates the encoder. The others find it by name. The encoder stays alive as long as some `obs_output` references it.
- Sharing a VideoConfig with a scene other than the main one also shares the `obs_view` (see 3.4).

### 2.4 Audio tracks
- Output track 0 uses the encoder `...-track-idx-0` with mixer `mixerId`.
- For each `audioTracks[i]` an encoder `...-track-idx-<output_track>` is created with mixer `mixer_track` (the `mixerId` parameter overrides the config's) and assigned via `obs_output_set_audio_encoder(output, enc, output_track)` (`push-widget.cpp:612-646`).
- The UI only allows **one** extra track (the "VOD Track"), with `output_track = 1` fixed (`edit-widget.cpp:953-962`). If the file contains several tracks, all are honored at runtime, but saving from the editor reduces them to one (`:1124-1131`).
- With an audio marker no extra tracks are added (`push-widget.cpp:613-614`).
- Non-multitrack outputs (the Rust one) ignore `idx>0` (OBS: `obs-output.c:1075-1100`).

### 2.5 Ids
`GenerateId()` returns the decimal value of a `std::random_device()` (uint32), retrying until it matches no id among targets, videoConfig or audioConfig (`output-config.cpp:324-337`). Targets and configs share the same id space.

### 2.6 enabled / syncStart / syncStop
- `enabled=false`: "Start all", the "start all" hotkey and sync start skip it, because `StartStreaming()` refuses to start it and shows `Status.Disabled` (`push-widget.cpp:1000-1003`). Unchecking it while the target is active calls `obs_output_force_stop` **only if `IsRunning()`** (`obs_output_active`) (`:1229-1238`). It can only be edited from the dock checkbox; the editor preserves it.
- `syncStart`: on `OBS_FRONTEND_EVENT_STREAMING_STARTING`, if the target is not busy, it is started (`:1104-1107`).
- `syncStop`: on `OBS_FRONTEND_EVENT_STREAMING_STOPPING`, if it is busy, `StopStreaming()` (which may ask about the delay) (`:1108-1111`).

## 3. Protocols and start/stop cycle

### 3.1 Table (`protocols.cpp:5-12`)
| `protocol` | UI label | `obs_output` id | `obs_service` id | Service tab (properties) | Output tab (properties) | Supported codecs (filter the encoder combos) |
|---|---|---|---|---|---|---|
| `RTMP` | RTMP | `rtmp_output` | `rtmp_custom` | `server`, `key`(pwd), `use_auth`, `username`, `password`(pwd) | `drop_threshold_ms`, `ip_family`, `bind_ip`, `new_socket_loop_enabled`, `low_latency_mode_enabled` (the last two Windows only) | v: h264;hevc;av1 (build-dependent) · a: aac |
| `SRT_RIST` | SRT/RIST | `ffmpeg_mpegts_muxer` | `rtmp_custom` (the `srt://`/`rist://` URL goes in `server`) | same as RTMP | `path` (not used in practice) | v: h264 · a: aac;opus |
| `RTMP_RUST` | RTMP/RTMPS (Rust session engine) | `multi_rtmp_rust_output` | **none** (`nullptr`) | empty (`ClearProperties`) | `server`, `key`(pwd), `backup_server`, `backup_key`(pwd) | v: h264 · a: aac |
| `WHIP` | WebRTC (WHIP) | `whip_output` | `whip_custom` | `server`, `bearer_token`(pwd) | (none) | v: h264;hevc;av1 · a: **opus** |

If the protocol does not exist, the first entry (RTMP) is used to create the output (`push-widget.cpp:1012-1017`), although `PrepareOutputService` fails with the log "Invalid protocol" (`:340-345`). The UI selector falls back to index 0.

### 3.2 `StartStreaming()` (`push-widget.cpp:993-1073`), in order
1. Returns if `IsBusy()` or if the CAS `isStarting_ false→true` fails. A `finally` guard resets `isStarting_=false` on every early return.
2. If `!enabled`: message `Status.Disabled` and return.
3. `ReleaseOutput()` (3.6): **the output is recreated on every start**.
4. `obs_output_create(outputId, "multi-output", obs_data_create_from_json(outputParam.dump()), nullptr)`. If `output-param` is `null`, the settings are NULL and defaults are used. Then the signals are connected (4.1).
5. Delay (`:1026-1042`): reads `obs_frontend_get_profile_config()` `[Output] DelayEnable`, `DelayPreserve`, `DelaySec` and calls `obs_output_set_delay(out, DelayEnable?DelaySec:0, DelayPreserve?OBS_OUTPUT_DELAY_PRESERVE:0)`. `isUseDelay_ = DelayEnable && DelaySec>0`.
6. `PrepareOutputService()` (`:324-365`): if a `service_` from a previous start still exists, error. If the protocol has no serviceId (Rust), OK. Otherwise: `obs_service_create(serviceId, "multi-output-service", obs_data_create_from_json(serviceParam.dump()), nullptr)` and `obs_output_set_service`. The plugin keeps **its own reference** in `service_`. If `service-param` is `null`, `conf` is NULL and the function **fails**. Any failure shows `Error.CreateRtmpService`, including when `output_` could not be created.
7. `PrepareOutputEncoders()` (`:593-650`): see 3.3. Failure → `Error.CreateEncoder` (the `Notice.GetEncoder` QMessageBox has already been shown before).
8. `PrepareEncoderSource()` (`:381-431`): see 3.4. Failure → `Error.SceneNotExist`.
9. `isBusy_ = true` and `obs_output_start(output_)`. If it returns false: `isBusy_=false`, `ReleaseOutput()` and `Error.StartOutput`.
10. On success: `resetStarting.Dismiss()`. `isStarting_` stays true until `OnStarted`/`OnStopped`.

`obs_output_set_reconnect_settings` is not called: libobs defaults apply (20 retries, 2 s initial, exponential growth ×1.5–1.55 and a 15 min cap; OBS: `obs-output.c:242-244`, `:32-33`). libobs only reconnects on `OBS_OUTPUT_DISCONNECTED`. The Rust output reconnects on its own and never emits `reconnect`.

### 3.3 Obtaining and creating encoders
`GetVideoEncoder()` (`:510-550`):
- STREAMING marker or `""`: the video encoder of the OBS streaming output. `using_main_video_encoder_=true`.
- RECORDING: the encoder of the recording output. `using_main_video_encoder_=true`.
- Own id: `obs_get_encoder_by_name("multi-rtmp-venc"+id)`. If it does not exist, the VideoConfig is looked up and `obs_video_encoder_create(encoderId, name, data(param), nullptr)` is called. If created: if `resolution` parses, `obs_encoder_set_gpu_scale_type(BICUBIC)` + `obs_encoder_set_scaled_size(w,h)`; always `obs_encoder_set_frame_rate_divisor(fpsDenumerator)`. If there is no VideoConfig: log, **`videoConfig = STREAMING` is rewritten in memory** and it retries. `using_main_video_encoder_=false`.
- Resolution and divisor **are only applied when the encoder is created**.

`GetAudioEncoder(trackIdx=0, mixerId=nullopt)` (`:552-591`): same as video, with track 0 of the main or recording output. In the own-config case: `obs_audio_encoder_create(encoderId, "multi-rtmp-aenc<id>-track-idx-<trackIdx>", data(param), mixerId ?? config.mixerId, nullptr)`.

`PrepareOutputEncoders`: video and audio track 0, then the extra tracks. If the video or track-0 audio encoder is missing (for example, "same as recording" with no recording output configured), it shows a **modal** critical QMessageBox `Notice.Title`/`Notice.GetEncoder` and returns false. Then it calls `obs_output_set_audio_encoder(out, aenc, 0)`, the extra tracks at their index, and `obs_output_set_video_encoder`.

### 3.4 Video source: scene and view (`PrepareEncoderSource`, `SharedSceneView*` `:73-200`)
- Only when the encoder is **not** an OBS one:
  - No VideoConfig or no `scene`: `obs_encoder_set_video(venc, obs_get_video())`, the main mix.
  - With `scene`: `obs_get_source_by_name(scene)` (if it does not exist: fails with "Output scene is not found") and `SharedSceneViewManager::Acquire(venc, scene)`:
    - The map `encoder* → weak_ptr<SharedSceneView>` is protected by a mutex. Expired entries are purged.
    - If a live view exists for that encoder: `SetSource(scene)` (changes the scene and adjusts `inc_active`/`dec_active`) and it is reused.
    - If the encoder is already active with no registered view: error.
    - Otherwise: `obs_view_create`, `obs_view_set_source(view,0,scene)`, `obs_source_inc_active(scene)`, `video = obs_view_add(view)` and `obs_encoder_set_video(venc, video)`, checking that `obs_encoder_parent_video(venc)==video`.
  - When the view is destroyed: `obs_view_remove`, `dec_active` on the current source, `set_source(0,null)` and `obs_view_destroy`.
- Audio (if the encoder is not an OBS one): `obs_encoder_set_audio(aenc0, obs_get_audio())` and the same for each extra track.
- Each `PushWidget` holds a `shared_ptr<SharedSceneView>` (`scene_view_`). It is released in `OnStopped` and in `ReleaseOutput`.

### 3.5 `StopStreaming()` (`:1075-1095`) and `Stop()` (`:1251-1257`)
- `StopStreaming`: only if busy. If `isUseDelay_`, opens a modal QMessageBox (literal title `"?"`, text `Ques.DropDelay`, Yes/No). Yes → `obs_output_force_stop`; otherwise → `obs_output_stop`.
- `Stop()`: if busy, `obs_output_force_stop` without asking. Used on EXIT, PROFILE_CHANGED and PROFILE_LIST_CHANGED.
- `StartStop()` toggles based on `IsBusy()` (`:1240-1249`).

### 3.6 Cleanup (`ReleaseOutput` `:653-674`)
1. Disconnects the 7 signals.
2. If the output is still active: `obs_output_force_stop`.
3. `obs_output_release(output_)`; `output_=nullptr`. Destroying the output clears the service's back pointer.
4. **Afterwards** `obs_service_release(service_)`, because releasing it earlier would leave a dangling pointer: libobs ignores `set_service(nullptr)` (comments at `:331-334`, `:367-369`).
5. `scene_view_.reset()`.

`ReleaseOutput` is only called **at the start of the next start**, when `obs_output_start` fails, and in the widget destructor (`:960-968`). After a normal stop, the `obs_output` (and with it its references to the encoders and the service) **stays alive** until the next start. See bug 7.3-#9.

### 3.7 RTMP_RUST path (`rust-session-output.cpp`)
Registration (`:374-393`): `id="multi_rtmp_rust_output"`, `flags = OBS_OUTPUT_AV | OBS_OUTPUT_ENCODED` (**without** SERVICE or MULTI_TRACK), `encoded_video_codecs="h264"`, `encoded_audio_codecs="aac"`, name "RTMP/RTMPS (Rust session engine)".
- Properties and defaults (`:76-93`): `server` ("Server (rtmp:// or rtmps://)"), `key` (pwd), `backup_server` ("Backup server (optional, e.g. YouTube b.rtmps...?backup=1)"), `backup_key` (pwd, "empty = same key"). All default to `""`.
- Per-output state (`RustOutput` `:21-30`): `mgr_mutex`, `SessionManager* mgr`, ids `primary`/`backup`, `origin_us=INT64_MIN`, `headers_sent`, `running`. A global registry `obs_output_t* → RustOutput*` guarded by `g_registry_mutex` serves queries from the UI.
- `Start` (`:118-190`):
  1. `obs_output_can_begin_data_capture`.
  2. Requires video and track-0 audio encoders with codecs `h264` and `aac`. Otherwise, last_error "Rust session engine only supports H.264 video and AAC audio" and false.
  3. Reads `server`, `key`, `backup_server` and `backup_key` from the output settings. If `backup_key` is empty, `key` is used. If `server` is empty, last_error "Missing server URL".
  4. `obs_output_initialize_encoders`, then `FreeManager` on the previous manager.
  5. `OmrStreamInfo`: encoder width and height, `fps = video_output fps / divisor`, video and audio bitrate (`bitrate` key of the settings; 0 if ≤0), sample rate and channels.
  6. Under the mutex: `omr_manager_new()` and `primary = omr_session_add_with_info(mgr, url, key, 0, 0, &info)`. If it returns 0: last_error "Invalid RTMP/RTMPS URL or stream key". If there is a backup: `omr_session_add_with_info(...)`; if it returns 0: "Invalid backup RTMP/RTMPS URL". Then it resets the origin and `headers_sent=false`, and sets `running=true`.
  7. `obs_output_begin_data_capture`; on failure, `FreeManager`. **The `start` signal is emitted synchronously here**, before `starting` (see 7.3-#5).
- `EncodedPacket` (`:246-283`), on the libobs encoder thread and under `mgr_mutex`: a null packet triggers `signal_stop(ENCODE_ERROR)`. With the first packet the headers are sent: `obs_encoder_get_extra_data(video)` → `obs_parse_avc_header` → `omr_set_video_extradata`, and the audio extra_data → `omr_set_audio_extradata`. On failure: last_error, `running=false` and `signal_stop(ENCODE_ERROR)`. `dts_ms = max(0, (dts_usec - origin)/1000)`, with the origin taken from the first packet. Video: `cts = pts*1000/den - dts*1000/den` and `omr_push_video(dts_ms, dts_ms+cts, data)`. Audio: only `track_idx==0`, `omr_push_audio`.
- `Stop` (`:192-207`): `obs_output_end_data_capture` (libobs emits `stop`). Under the mutex: `running=false`, `omr_session_remove` for primary and backup (non-blocking) and `omr_clear_headers`. Then `FreeManager` outside the mutex (`omr_manager_free` joins the threads, with time bounded by the socket timeouts).
- `GetTotalBytes` and `GetDroppedFrames` return statistics of the **primary** session only.
- UI API: `GetRustOutputStatus` (`:307-338`) returns the state of primary and backup (`RS_NONE=-1` if there is no backup), dropped video frames of each session, the sum of reconnections and of queued bytes, and the `last_error` of the first session that is not LIVE. `ControlRustSession(slot, Pause|Resume|Restart)` (`:340-372`) calls `omr_session_pause/resume/restart`; it only works if `running` and the id exists, and writes a log entry.
- States: `0 idle, 1 connecting, 2 LIVE, 3 backoff ("retry"), 4 stopped, 5 paused` (`rust-session-output.h:21`).

### 3.8 Null service and output for the main stream (`null-stream.cpp`)
- Output `multi_rtmp_null_stream_output`: `flags AV|ENCODED|SERVICE`, `protocols="MULTI_RTMP_NULL"`. `start` does can_begin, initialize_encoders and begin_data_capture. It discards every packet. bytes=0 and drops=0 (`:49-117`).
- Service `multi_rtmp_null_service`: protocol `MULTI_RTMP_NULL`, `get_output_type` = the null output, connect_info `""`, `can_try_to_connect=true` (`:13-45`, `:119-128`). OBS 33 picks the output for the "Start Streaming" button based on the service, so the OBS encoders keep running but nothing is sent.
- `IsMainStreamNull()`: the current service id equals the null one (`:131-135`).
- `SetMainStreamNull(enable)` (`:137-180`): fails with `MainStreamNull.StopFirst` if OBS is streaming. If the state is already the requested one, it does nothing.
  - Enable: creates `multi_rtmp_null_service` with the name `"default_service"` and the settings `{original_type: <service id>, original_settings: {...}, original_hotkeys: {...}}`. OBS saves them in the profile's `service.json`.
  - Disable: recreates `original_type` (`rtmp_common` if missing) with `original_settings` and `original_hotkeys`.
  - Then `obs_frontend_set_streaming_service` + `obs_frontend_save_streaming_service`. If creation fails: `MainStreamNull.Failed`.

### 4.1 Connected signals (`push-widget.cpp:254-283`) and what each handler does (everything goes through `RunInUIThread` with a `WeakThis` guard)
| Signal | Handler | Effect (`:1266-1378`) |
|---|---|---|
| `starting` | OnStarting | `begin_time_=now`, `isConnecting_=true`, `isReconnecting_=false`, `lastErrorCode_=0`, button `Status.Stop` enabled, message `Status.Connecting`, dot |
| `start` | OnStarted | `isStarting_=false`, `isConnecting_=false`, `isReconnecting_=false`, button `Status.Stop`, message `Status.Streaming`, `ResetInfo()`, starts the 1 s timer, dot |
| `reconnect` | OnReconnect | stops the timer, `isReconnecting_=true`, message `Status.Reconnecting`, dot |
| `reconnect_success` | OnReconnected | `isReconnecting_=false`, message `Status.Streaming`, `ResetInfo()`, starts the timer, dot |
| `stopping` | OnStopping | stops the timer, message `Status.Stopping` (does not touch the dot) |
| `deactivate` | onDeactive | nothing |
| `stop(code)` | OnStopped | releases the scene view, `isBusy_=false`, clears all flags, `lastErrorCode_=code`, `ResetInfo`, stops the timer, button `Btn.Start` and the code's message (table), `UpdateStatusDot(true)` |

Stop codes → message (`:1354-1374`): `0`→"" · `-1` (BAD_PATH)→`Error.WrongRTMPUrl` · `-2` (CONNECT_FAILED)→`Error.ServerConnect` · `-3` (INVALID_STREAM)→`Error.ServerHandshake` · `-4` (generic OBS_OUTPUT_ERROR)→`Error.ServerRefuse` · anything else (-5 DISCONNECTED, -6, -7, -8 ENCODE_ERROR, -9)→`Error.Unknown`. `obs_output_get_last_error` **is never shown**.

`SetMsg(t)` sets the text and the tooltip (`:1259-1263`). `ResetInfo()` sets frames and bytes to 0, `last_info_time_=now` and the message to "" (does not reset `begin_time_`) (`:1199-1205`).

### 4.2 Status line (1 s timer, `UpdateStreamStatus` `:677-737`)
- `interval` = seconds since the last tick. If `>0`:
  - Duration since `begin_time_` (set on `starting`): `"%02d:%02d:%02d"`.
  - FPS: `round((total_frames - prev)/interval)` using `obs_output_get_total_frames`, formatted as `"%d FPS"`.
  - Bitrate: `bps = Δbytes*8/interval` using `obs_output_get_total_bytes`. If `bps>0`: `idx = floor(log10(bps)/3)` (capped at 8), `val = to_string(bps/1000^idx).substr(0,4)`, removing a trailing `.` if left, plus `" "` and the unit from `[bps,Kbps,Mbps,Gbps,Tbps,Pbps,Ebps,Zbps,Ybps]`. Otherwise `"0 bps"`. Examples: 2,500,000 → "2.50 Mbps"; 123,456,789 → "123 Mbps".
  - Line: `"HH:MM:SS  <bitrate>  <N> FPS"` (two spaces between fields) plus the Rust suffix. Applied with `msg_->setText`, and the tooltip becomes `rustStatusTip_` (empty if the target is not Rust: this **clears** the previous tooltip).
- Rust suffix (`RustStatusSuffix` `:743-765`), only if `protocol=="RTMP_RUST"` and there is a status: `"  [" + state(primary)`; if there is a backup, `" | backup " + state`; if any drop counter is non-zero, `"  drop P"` or `"  drop P/B"`; if there are reconnections, `"  recon N"`; finally `"]"`. State names: `idle, connecting, LIVE, retry, stopped, paused`, and `?` for out-of-range values. `rustDegraded_ = primary≠LIVE || (backup exists && ≠LIVE)`. `rustStatusTip_ = last_error`.
- Each tick also calls `RefreshRustControls()`, but **not** `UpdateStatusDot()`.

### 4.3 Status dot (`UpdateStatusDot` `:836-850`)
A QLabel `"●"` whose color is set with `setStyleSheet("color: X;")`. Priority:
1. `#e6b800` (yellow) if `isReconnecting_ || isConnecting_ || (!stopped && rustDegraded_)`
2. `#2ecc71` (green) if `!stopped && IsRunning()` (`output_ && obs_output_active`)
3. `#e74c3c` (red) if `lastErrorCode_ != 0`
4. `#888888` (gray) when idle

It is called in the constructor, in `UpdateConfig`, in `SetEnabled` and in the starting/start/reconnect/reconnect_success/stop handlers.

### 4.4 Per-session Rust controls (`BuildRustControls` `:795-834`, `RefreshRustControls` `:779-793`)
- Grid row 2 (spanning 3 columns), hidden by default. It has two boxes: `Rust.Primary` ("Live:") and `Rust.Backup` ("Backup:"), each with a pause QToolButton (`⏸`, tooltip `Rust.Pause`, or `▶` with tooltip `Rust.Resume` when paused) and a restart button `⟳` (tooltip `Rust.Restart`). There is 12 px spacing between the two and a stretch at the end.
- Visible only if not stopped, `output_` exists, `protocol=="RTMP_RUST"`, `IsRunning()` and `GetRustOutputStatus` succeeds. The backup box is hidden if `backup==RS_NONE`. The pause icon reflects `state==RS_PAUSED`.
- Pressing pause toggles based on `rustPaused_[i]`: `ControlRustSession(Pause|Resume)` and, on success, updates the icon. Restart: `Restart` and, on success, the icon returns to "not paused".

## 5. Frontend events and hotkeys

### 5.1 Event callback (`obs-multi-rtmp.cpp:696-718`), always on the UI thread
For each event, in this order:
1. `OnOBSEvent(ev)` on every PushWidget (including the "staged" ones):
   - `EXIT`, `PROFILE_CHANGED`, `PROFILE_LIST_CHANGED` → `Stop()` (force stop).
   - `STREAMING_STARTING` → sync start.
   - `STREAMING_STOPPING` → sync stop (`push-widget.cpp:1097-1113`).
2. `FINISHED_LOADING` → `frontendReady_=true`; `EXIT` → `frontendReady_=false`.
3. `RefreshNullStreamCheck()` on **every** event: if `frontendReady_`, checks the box according to `IsMainStreamNull()` and enables it if `!obs_frontend_streaming_active()`. It is also called from the dock's `showEvent` (`:600-604`).
4. `EXIT` → `SaveConfig()`; `PROFILE_CHANGED` → `LoadConfig()`.

Recording events are not handled: "same as recording" is not synchronized with recording.

### 5.2 Hotkeys (`obs_hotkey_register_frontend`)
| Name | Description | Action | Ref |
|---|---|---|---|
| `obs-multi-rtmp.start_all` | `Hotkey.StartAllTargets` | `StartStreaming()` on all | `obs-multi-rtmp.cpp:669-680` |

### 6.3 "Edit targets" dialog (`edit-targets-dialog.cpp`)
- Input: `SerializeMultiOutputConfig(global)` plus a `GlobalEditSnapshot` built on open: the ids of widgets with `IsBusy()` and their video and audio configs, if any (`obs-multi-rtmp.cpp:187-204`). The dialog works on **a deserialized copy**, modally (`exec`).
- Title `EditTargets.Title`. Horizontal QSplitter:
  - Left: buttons `+` (`Btn.AddTarget`), `-` (`Btn.RemoveTarget`), stretch, `↑` (`Btn.MoveUp`), `↓` (`Btn.MoveDown`), with minimum width 40, and a QListWidget with the names (an empty name shows as `NewStreaming`).
  - Right: QStackedWidget with the placeholder `EditTargets.Empty` (disabled, centered) or one QScrollArea page per target containing an `EditTargetPanel`. Pages are created lazily on selection.
  - Footer: `Btn.ExportConfig`, `Btn.ImportConfig`, stretch, `OK`, `Cancel`.
- Changing selection runs `CommitCurrent()` (`panel->SaveConfig()` and refresh of the name in the list) and shows the page.
- Add: commit, new `OutputTargetConfig` with `GenerateId()` and default values, which gets selected.
- Remove: no confirmation and no commit. **Disabled if the target is in `snapshot.activeTargetIds`.**
- Move up/down: commit and swap in the list and in `config_.targets`.
- OK: `CommitCurrent()` and `accept()`, and the dialog returns the serialized JSON. Cancel returns `nullopt`.
- Initial size computed from the panel and clamped to the screen. Has a size grip (`:62-84`, `:479-485`).
- **Apply** (`ApplyEditedConfig`, `obs-multi-rtmp.cpp:506-582`):
  1. Keeps a copy of the old configuration and detaches all widgets (they go to staging).
  2. `UpdateConfig(edited, ctx)` on each old widget (details below).
  3. `global = edited`.
  4. Walks `global.targets` in order: reattaches the existing widget or creates a new one.
  5. Remaining widgets (deleted targets): if not busy, `deleteLater`. If busy, they are **added back** to `global.targets` (with their video and audio configs taken from the old configuration if missing), reattached, and their name goes to `failedDeletes`.
  6. `SaveConfig()`.
  7. If there are notices: an informational QMessageBox `Notice.Title` with the unique notices from `ctx.notices` and, if there were failed deletes, `Notice.DeleteFailed` plus one name per line.
- `PushWidget::UpdateConfig(new, ctx)` (`push-widget.cpp:1122-1197`):
  - If `protocol` or `serviceParam` changed → notice `Notice.ServiceChanged` (even if the target is **not** active).
  - If the video or audio id changed and the target is busy → `Notice.EncoderConfigChanged`.
  - Same video id but different config (`VideoConfigEqual`: encoder, fps, params, scene, resolution): if the encoder `multi-rtmp-venc<id>` exists, `UpdateEncoderSettings` (once per id thanks to `ctx.updatedVideoConfigIds`) and, if busy, `Notice.EncoderParamsChanged`.
  - Same audio id but different config: for each track in `{0} ∪ old tracks ∪ new tracks` whose encoder `multi-rtmp-aenc<id>-track-idx-N` exists, `UpdateEncoderSettings` (once per name) and, if busy, the same notice.
  - Then `config_ = newTarget`, `LoadConfig()` (name and checkbox), dot, and `UpdateSceneView(new)` if the video id did not change (the view's scene is switched live; if the scene does not exist, warning and the current one is kept).
- `UpdateEncoderSettings(enc, old, new)` (`:35-71`): `merged = new`. For each key of `old` not present in `new`, it takes the encoder's default value (`obs_encoder_get_defaults`) or, if none, the current or old value (with a warning). Then `obs_encoder_update(enc, merged)`, without clearing the live settings first.

  - `Scene` combo: if locked (active target or active VideoConfig), items that would change mode are disabled: you cannot switch from "default scene" to a specific scene or vice versa, but you can switch between specific scenes (`UpdateSceneModeLock` `:825-852`).
  - Everything else (name, protocol, service, output, resolution, FPS, encoder parameters, mixer, VOD, sync) **stays editable**. Those changes are only applied live where 6.3 says so.
- Encoder change (`:640-649`): `SaveConfig(); LoadConfig(); UpdateUI()`. Switching from a marker to a real encoder creates a new config with `GenerateId()`. Switching from one real encoder to another **keeps the id**, which affects every target sharing it. The previous encoder's parameters are saved with the new `encoderId`.
- Protocol change (`:654-661`): `SaveConfig` (saves the previous protocol's service and output params), `LoadConfig`, `UpdateUI`, and rebuilds the service and output tabs. Leftover keys are carried over.

## 7. Threads, concurrency and known issues

### 7.1 Threads
| Source | Thread | Handling |
|---|---|---|
| Frontend events, UI clicks, timer, dialogs | UI (Qt) | direct |
| `obs_output` signals (`start`, `stop`, `reconnect`…) | libobs threads (connection or encoder) **or the UI thread** (for example `starting`, and `start` on the Rust output, which are emitted inside `obs_output_start`) | `RunInUIThread` with a `WeakThis` guard (`push-widget.cpp:852-868`) |
| Hotkey callbacks | **libobs hotkey thread** (`obs_hotkey_thread`, OBS: `obs.c:1164`) or the UI thread (injected events) | **none**: they call `StartStreaming`/`StopStreaming` directly |
| `EncodedPacket` (Rust) | libobs output/encoder thread | `mgr_mutex` |
| `GetRustOutputStatus`/`ControlRustSession` | UI | `g_registry_mutex` → `mgr_mutex` (always in that order) |
| `omr_manager_free` | whichever thread calls stop/destroy | outside `mgr_mutex` |

- `RunInUIThread` (`obs-multi-rtmp.cpp:25-43`) calls `QMetaObject::invokeMethod(QThread* uiThread_, fn)` with `AutoConnection`: if already on the UI thread, **execution is synchronous**; otherwise it is queued. It returns false until `uiThread_` is set, which happens via a queued invocation in `obs_module_load` (`:654-656`). Earlier signals are dropped with a warning.
- `WeakThis`: the `shared_ptr<void>` token dies with the widget, and queued lambdas check `Get()` (`helpers.h:15-40`).
- Atomics: `isStarting_` (CAS against reentrancy) and `isBusy_`. The other flags (`isConnecting_`, `isReconnecting_`, `lastErrorCode_`, `output_`) should only be touched from the UI.
- Mutexes: `SharedSceneViewManager::mutex_` (map) and `SharedSceneView::source_mutex_` (`SetSource`); `g_registry_mutex` and `RustOutput::mgr_mutex`.
- `isBusy_` is cleared on the UI thread inside the `stop` lambda so as not to delete a widget that has a pending lambda (commit `53d2bf7`, `push-widget.cpp:1339-1342`).

### 7.2 Rules the reimplementation must preserve
1. Release the `obs_service` only **after** destroying the `obs_output` that uses it.
2. Do not reassign the video of an active encoder. One shared scene view per encoder, reference-counted.
3. Marshal any output signal to the UI thread, and also **the hotkeys**. Modal windows (`Ques.DropDelay`, `Notice.GetEncoder`) may only be opened on the UI thread.
4. Do not destroy properties widgets inside their own signal handler (`deleteLater`).
5. Keep tolerant JSON reading and writing (2.x), with sorted keys, BOM on save and GC of unreferenced configs.

### 7.3 Observed bugs and risks
1. **FLOAT saved as integer**: `obs_data_set_int(..., std::stod(...))` (`obs-properties-widget.cpp:263`).
2. Unsupported properties (GROUP, PATH, etc.), and `enabled`, limits and disabled list items are ignored (6.5). Encoders whose properties are inside groups cannot be edited.
3. **Hotkey bindings not persisted** across restarts (5.2).
4. **Hotkeys run on the hotkey thread**: they touch Qt widgets and can open QMessageBoxes outside the UI thread (`obs-multi-rtmp.cpp:672-691`, `push-widget.cpp:939-956`).
5. **start/starting order on the Rust output** (the targets' output; the main-stream null output is not affected because it has no PushWidget): `begin_data_capture` emits `start` inside `obs_output_start` (OBS: `obs-output.c:2799-2800`) and `starting` is emitted afterwards (`:409-411`). Since `RunInUIThread` is synchronous on the UI thread, `OnStarted` runs and then `OnStarting`, which leaves `isConnecting_=true`. Result: the text stays at "Connecting" until the first tick and **the dot stays yellow** while the output is alive, because the timer does not repaint the dot. `rustDegraded_` does not repaint the dot between events either.
6. `PROFILE_LIST_CHANGED` (creating, renaming or deleting a profile) force-stops **all** targets (`push-widget.cpp:1099-1103`).
7. `Notice.ServiceChanged` appears even if the target is not active (`push-widget.cpp:1133-1136`).
8. Encoder not available in the combo: the target silently becomes "same as OBS" on save, and the orphaned config disappears from the file (`edit-widget.cpp:1030-1038`, `976-983`).
9. **Stopped outputs are not released** until the next start (3.6). A shared encoder can stay alive in another target's stopped output, and is then reused with an old resolution or FPS divisor: `UpdateEncoderSettings` only changes params, never `scaled_size` or `frame_rate_divisor`.
10. If `service-param` is `null` (missing from the file), start fails with `Error.CreateRtmpService` (`push-widget.cpp:352-354`).
11. `obs_output_get_last_error` is never shown; for example, Rust URL or codec errors are only visible in the log or in the Rust status tooltip. Code -4 (generic) is shown as "connection refused".
12. `SetEnabled(false)` does not stop a target that is connecting but not yet active: it uses `IsRunning()` instead of `IsBusy()` (`push-widget.cpp:1234`).
13. `Question.Import` says active targets will be stopped, but they are not: they are kept and appear in `Notice.DeleteFailed` if they are not in the import.
14. The "active" snapshot is taken when the dialog opens and is not refreshed while it is open: a target can start via sync or hotkey with the dialog open.
15. The "Share" menu offers the markers as if they were shared configs, in an undefined order.
16. The UI only supports one VOD track, with `output_track=1` fixed. If an extra track has `output_track=0`, it collides with the main encoder's name.
17. FPS label without zero padding in the decimals (`edit-widget.cpp:738-743`).
18. Per-target hotkey descriptions are not updated on rename. Global hotkeys are never unregistered.
19. `PushWidgetImpl` with a nonexistent id leaves the UI pointers null (the constructor returns early, `push-widget.cpp:878-880`), risking a crash if used later.
20. `RTMP_RUST`: the bitrate and drops shown by OBS are only those of the primary session. Only audio track 0. Only H.264+AAC.
21. Null service: if the user opens Settings → Stream in OBS while the null service is active, OBS may not recognize it (it is not in its list). Not verified; worth testing.
22. Dead code: `EditOutputWidget`/`createEditOutputWidget`, `plugin-main.c`, `IOBSOutputEventHanlder::onDeactive`, and the `mainOutput`/`recordingOutput` variables in `PrepareOutputEncoders` (`push-widget.cpp:603-607`).
